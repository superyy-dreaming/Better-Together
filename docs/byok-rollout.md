# 设备 BYOK 切换与回滚

适用于部署 202611210020 及以后版本。不得回滚到后端持有 AI 密钥或代理用户请求的架构。非 AI 任务、原图、历史纪要、账号和周报必须保留。

1. 在独立临时 PostgreSQL 执行历史迁移回归，再执行追加迁移与 BYOK 回归；Flutter 分析、相关测试和原生构建通过。
2. 部署 recognize 的升级响应及禁用 AI/report 的 worker，先停止新代理调用与旧 AI 任务执行。现有已领取调用可能尚在运行；追加迁移吊销租约并禁用旧结果写入。
3. 追加 020 迁移。移除现存 ai_settings 密文表，旧 queued/processing AI/report job 进入 dead；保留所有非 AI job。新结果保存采用鉴权、数据结构、来源、记录版本、照片 revision、小队 scope 和幂等检查。
4. 部署 api 与 media；仅接受 BYOK 业务结果，不接收密钥。旧 AI 配置接口返回升级提示，旧 recognize 返回可降级 pending 的响应。
5. 删除运行中 Edge Secrets 和本机安全配置中的 OPENAI_* / AI_SETTINGS_*。只报告名称与检查状态，不输出密钥或密文。JOB_SECRET 和推送密钥保留。
6. 合成账号验证无配置、错误配置和超时仍可归档盖章；用户在 App 安全表单重新填写 Key 后才运行真实供应商复测。旧云端 Key 不迁移到设备。
7. 构建 Release，覆盖安装，保留设备登录与数据。

回滚：保留追加数据库结构，部署无后端 AI 的兼容版本；必要时停用本机 AI，保持照片归档、ALL 盖章、手动编辑和规则周报。不得恢复旧 ai_settings、旧供应商转发或从备份恢复密钥。

当前活跃配置清除不等于供应商撤销，也不能证明历史备份/PITR/旧部署物已物理清除。持有人需在供应商处撤销旧密钥；无法核实的保留物在验收中单列。历史 SQL 迁移不改写，代码快照仅保留无密钥源码。
