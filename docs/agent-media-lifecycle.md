# 原图归档与登记边界

修改上传、重试、补偿或清理代码时读取此文件。

Storage 和 PostgreSQL 是两个独立提交域。网络错误、503 或进程中止只能证明调用方未收到成功，不能证明写入未提交。禁止据此删除原图或重置业务记录。

media 与 media_analysis 必须在同一个幂等事务内登记，身份绑定 owner、batch、photo_id、来源、原图和分析图实际摘要。相同身份重放不覆盖已验证结果、不延长临时像素有效期；不同身份必须冲突。提交成功但响应丢失应由同身份重试读到已提交结果。

Storage 使用不可覆盖的确切路径。未知上传结果或路径已存在时，读取原对象并核对实际大小/SHA256后才继续；不得盲目 upsert。不能证明对象未被引用且不会被并发登记时，保留对象并记录恢复状态。清理必须先取得该上传身份的排他处置权，再核验引用，不能用日志事件替代引用与所有权检查。

原图归档、缩略图派生和媒体授权属于不同阶段。盖章不能等待缩略图；派生图只使用已校验的分析像素，不读取或重传原图，不依赖 Storage Image Transform。旧照片没有缩略图时明确回退原图读取，再由客户端缓存。

缩略图关联更新必须返回实际更新行，零行不是关联成功。上传期间若删除已完成，只能凭同 owner、batch、media ID 的终态删除标记清理对应不可覆盖的派生路径，不能连带删除原图。关联或清理响应丢失时报告 pending 并同身份重试；行缺失不等于拥有删除授权，未知孤儿对象保留供核对。验收包括删除赢上传竞态、上传/关联/清理响应丢失与未知归属不误删，见 `supabase/functions/_shared/thumbnail_test.ts`。

头像也采用新对象路径与资料引用分步确认。客户端校正方向并生成 512×512 JPEG，服务端核验实际格式、尺寸和归属后直接存私有桶；引用更新失败保留旧头像，未知提交结果不能触发盲删。不要重新引入 Image Transform 作为头像上传前置依赖。

验收至少包含：数据库已提交但响应失败、Storage 已保存但响应失败、缓存写失败、读取暂不可用、并发同身份、并发异字节，以及重试不延长 TTL。数据库原子性与互斥必须用真实临时 PostgreSQL 验证，网络故障由合成 fixture 注入。
