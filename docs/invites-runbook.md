# 小队短码与扫码

## 契约

新邀请码为 8 位，使用 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，不含易混淆的 0/O/1/I。客户端手输允许小写、空格与分组连字符；服务端执行同样规范化。数据库仅保存 SHA-256，密码学随机生成并对唯一冲突重试。保留旧 48 位十六进制邀请，7 天有效期和小队 5 人上限不变。

加入仍需登录。每账号每 15 分钟最多尝试 10 次，每小时最多生成 30 次。拒绝结果以数据库 JSON error 返回，确保失败尝试计数提交；Edge 再映射为 HTTP 400/429，不能在数据库内抛异常回滚计数。服务端邀请码错误不泄露目标小队信息。已生成邀请不会因再次生成被撤销。

扫码由 mobile_scanner 7.5.0（BSD-3-Clause）完成，iOS 使用 Vision/AVFoundation，Android 使用随包 ML Kit，无首次下载依赖。相机仅在扫描页开启，识别成功后先停止再返回，进入后台停止，离开时释放；识别结果回填后需用户确认加入。只接受应用 scheme、配置好的 APP_LINK_HOST 或有效邀请码，不自动打开任意扫描网址。相机不可用时提示并保留手输入口。

## 部署与回滚

1. 运行本地 SQL、Flutter 与 Edge 针对性测试，检查 016 的迁移 dry-run 只有本次追加迁移。
2. 先发布兼容旧 RPC 的 api 函数，支持提交后的邀请错误信封；再应用 `202611190016_short_invites.sql`。不修改已有邀请或成员记录。
3. 用独立合成账号执行建队、生成短码、格式化短码加入、错误邀请码和防猜限制。只记录状态，邀请码、凭据和用户数据不写公共日志。
4. 构建并覆盖安装 iOS Release，保留已登录会话。Android 原生扫码及页面使用模拟器验收；真实相机对屏幕二维码需要设备测试。
5. 回滚客户端可用上一 Release；后端如需回退，只将公开 app_action 路由还原到受保护的 `app_action_before_short_invites`，保持原有权限，保留 invites、成员及速率计数表。既有短码是正常 hash，旧实现仍能处理精确大写短码。不要删除成员、重置小队或清空邀请。

## 验证边界

Flutter 单元/组件测试验证解析、错误输入、扫描后确认、防重和宽度 375/768/1024/1440 的浅深色大字号。原生截图来自模拟器而非浏览器。iPhone 相机打开与二维码识别已由用户实测确认；Android 物理相机及各平台授权拒绝后的系统设置恢复仍需实际设备检查。
