# BYOK 识别优化执行记录

按用户批准的九步方案顺序执行。每步报告真实耗时和失败率，不能把模拟或缺失数据当作实测。

## 当前阶段

第 1、2 步已完成。第 2 步首轮发现候选计划数组嵌套缺陷，追加迁移 021 修复后已在 iPhone 17 Pro Max Release 上完成四场景各 5 次复测。后续所有性能测试按用户要求使用 Xcode iOS 模拟器；第 3 步先采集同一模拟器的改造前基线，再实施并发上限四并复测。真机与模拟器数据分开报告。

第 1 步仅新增脱敏计时。第 2 步已通过 Flutter analyze、143 项 Flutter 测试、47 项 Edge 测试、四入口类型检查及数据库回归。云端 recognize 已停用代理，当前后端 AI Key 与密文表已删除；非 AI 任务保留。

基准工具：`app/tool/ai_benchmark.dart`、`scripts/prepare_ai_benchmark.py`、`scripts/report_ai_benchmark.py`。独立入口复用现有压缩、CheckinDraft、仓库和 RecognitionCard，不初始化持久 Supabase 会话。测试账号与用户账号隔离，素材感知哈希最小两两距离为 20，没有关闭去重。

实验条件：superpotato（iPhone 17 Pro Max），Release，Asia/Shanghai 日期，2 个相同配置的私有候选计划。每次运行使用独立合成账号；AI 仍经当前旧代理及现存服务端配置。自动确认排除人工思考时间。测试启动参数仅阻止自动锁屏，以维持前台实验条件；退出测试程序后恢复正常启动行为。

测量边界：首图可见指确认页完成该卡片渲染；屏幕以下卡片不等于用户已经滚动看到。供应商等待包含网络、排队和响应处理，不能据此宣称纯模型推理耗时。失败样本保留，不能计作性能改善。

## 第 1 步观察到的现有生命周期

```text
选图返回 → 顺序读原图 → 各图异步压缩 → Edge recognize
                                      ├ 鉴权 / 日期上下文 / 候选计划 / 图片解码
                                      └ 供应商：截图 OCR → 纪要；照片仅纪要
             ← 单图 ready / pending / rejected ← 签名识别结果
确认页 → 逐图私有归档 → submit_checkin（幂等）→ 盖章返回
                         └ 数据库 jobs → 服务器补识别 → 版本检查 → 详情
```

- 控制面：当前账号、照片与批次身份、客户端识别版本、服务端签名及记录版本。
- 数据面：压缩图在识别请求中传输；确认后原图与分析图提交归档。
- 业务面：AI pending 不撤销盖章；明确凭证拒绝仍阻止该图片归档。
- 观测面：Server-Timing 与客户端 Stopwatch；观察不到保存响应时只能标记未确认，再按记录身份核查。
- 清理面：本步不删除照片、测试账号、任务或用户配置。测试登录文件读取后从手机移除；不会修改用户持久登录。

已观察到 9 图场景 HTTP 546。Supabase 官方 [状态码说明](https://supabase.com/docs/guides/functions/status-codes) 将其定义为执行超过资源限制；仅凭此状态不能区分 CPU、内存或并发资源。截图场景一次 `http_0` 未收到盖章响应，但只读核查确认对应记录已 stamped，证据位于 `output/ai-byok/step1-stamp-reconciliation.json`。

不含密钥的原始源码快照：`output/ai-byok/step0-source.tar.gz`。没有 Git 仓库；保留已有工作文件，不覆盖其他任务改动。

## 固定决定

- BYOK 仅设备安全存储，App 直连 Chat Completions；不从旧服务器导出密钥到设备。
- App 活跃时继续任务，系统挂起后回到 App 恢复；当日自动重试及手动补生成分别处理。
- 新运动数值只允许截图或现存设备来源；历史手填保留，不计入有来源运动统计。
- 基准素材使用合成图。真实 Keep 未验收，截图保持 1600，普通照片仅在第 5 步改到 1024。
- 逐图摘要独立于归类。没有 API 或 AI 失败不阻止合格照片盖章。
- 所有基准调用只使用专用合成账号；不替换用户的持久登录，不删除真实记录。

## 第 1 步结论

- 四场景各五次；单图／截图／3 图／9 图整批中位数分别 11.983／13.173／11.216／22.036 秒。
- 有效结果分别 4/5、5/5、15/15、35/45；待补 11 张包含 8 个 HTTP 546，不将快速失败算作提速。
- 供应商调用是有效识别的主要等待段。9 图原图归档中位数 15.861 秒，来自当前逐张归档链路，与识别本身分别报告。
- 20 次实际记录均保存：19 次收到盖章确认，1 次响应未确认后只读核查已 stamped。该次确认时长缺失，截图的“选图至盖章”中位数仅包含 4 个已观察响应，不能声称 5 个完整时长。
- 合成截图完整日期 5/5、距离／时长／热量字段均正确，但现有摘要过滤将数值句替换为占位句的现象已真实复现，按第 8 步解决；不能将结构 ready 当作摘要验收通过。
- 原始证据导出前扫描现有 AI／服务密钥与测试密码，未发现凭据。

### 第 2 步首轮缺陷

真实结果复核发现所有自动归类都为 ALL。云端实查 `ai_context.plans` 为双层数组，根因是对已返回 JSON 数组的 `ai_plan_candidates` 再做 jsonb_agg。首轮 20 次保留为缺陷证据，不作为第 2 步验收通过。追加 021 修复，增加 SQL 结构测试与客户端防御校验；基准入口在计时前检查两项候选，并记录生命周期及配置元数据指纹，再重跑四场景各五次。
