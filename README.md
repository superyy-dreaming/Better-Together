## 0. 项目速览（所有提示词的共同背景）

**一句话定位**：给「有计划、难坚持」的人用的跨品类小队打卡工具。每个人定自己的计划，每天拍照或上传当天照片证明完成，提交即盖章，AI 自动归类并把照片变成一条结构化纪要，周日自动汇成一份能发给队友看的周报。监督来自队友的眼睛：点赞、评论、质疑与戳一下，不来自押金和惩罚。

| 项 | 口径 |
|---|---|
| 首发品类 | 学习 / 饮食 / 运动 3 类，另支持自定义计划 |
| 小队 | 2–5 人私密小队，各定各的计划；也支持单人模式 |
| 核心闭环 | 定计划 → 打卡（默认 ALL）→ AI 验日期 + 自动归类 + 生成纪要 → 提交即盖章 → 小队动态（点赞 / 评论 / 质疑）→ 周日周报 |
| 周期 | 以周为周期，周日 20:00 出周报 |
| 资金 | App 不经手任何钱：不做押金、对赌、分钱、红包池 |
| 差异点 | 跨品类打卡 + 拍照证明 + AI 结构化纪要 + 给队友看的叙事周报，这个完整组合市面暂无同类做全 |

**已有交付物（派活时一并指给 agent）**：

- 《打卡 App MVP 流程说明 V1.1》PDF，10 页：主流程、单次打卡闭环、三类纪要规则、组队监督、提醒补卡异常、周报激励、页面清单与数据结构、验收与迭代。
- 可交互原型 UI（最新版）：今日、打卡、AI 归类 + 纪要、小队、周报、我的计划、设置等屏，可真实走通「打卡 → 盖章 → 小队动态新增一张卡」的闭环。
- 《打卡 App 市面调研》：25 款竞品核查，结论与红线来源。

## 1. 项目总开发提示词（整项目派活用）

```text
你负责开发一款跨品类小队打卡 App 的 MVP，产品暂名「打卡 App」。

产品定位：

给「有计划、难坚持」的人用：2–5 人组私密小队，每人定自己的计划（学习 / 饮食 / 运动三类起步，可自定义），每天拍照或上传当天照片证明完成，AI 自动归类并生成结构化纪要，每周日 20:00 自动生成可发给队友看的周报。卖点是「有证据的坚持」，不是游戏化数值。

核心流程，必须跑通这一圈：

建队（邀请链接/二维码，上限 5 人）→ 每人独立定计划（品类、目标、频率、打卡时段、截止时间、证明方式、可见范围；一人最多 3 个进行中计划）→ 每日打卡 → 队内监督 → 周日周报 → 按周报微调下周计划。

单次打卡规则，逐条实现，不要自行改动：

1. 打卡页默认选中 ALL，不选计划也能直接上传；AI 按内容把每张图自动归到对应计划，同一批多图可拆分归类，结果带置信度在确认页逐张展示。
2. 上传来源三种：App 内实时拍摄；相册选图（必须读 EXIF 拍摄日期、为打卡当天，无 EXIF 看文件创建时间，两者都缺失则拦截该张并提示换图或改实拍，不计作弊、不留负面记录）；运动类可上传 Keep 等运动 App 的当天截图，识别画面内日期、项目、时长、距离。
3. 多图：每次可传多张（上限见待定项，先做成可配置常量，不要写死），逐张验日期，非当天单张剔除并提示，全部非当天才整单拦截。
4. 识别不准时：用户在确认页点对应计划标签改归类，点「按此标签重新打卡」重生成纪要；盖章后 24 小时内仍可改标签，连续记录随之转移，不算重打。完全识别不出时不拦截，挂 ALL 下生成通用纪要并盖章，周报单列「未归类」。
5. 提交即盖章成功。不设「存疑 / 待确认」状态，不要恢复这个状态。状态只有：待打卡 → 已提交（识别中）→ 已盖章 →（被质疑过半）待重打 → 重打后重新盖章；补卡是独立状态「已补卡」，如实标注。
6. AI 失败或超时：照片先存、先盖章，纪要位显示「纪要生成中」，当天内补出。
7. 同一张照片（感知哈希相同）全队范围内只能用一次，重复上传直接提示已用过。不做人脸核身、不查定位。

三类纪要口径，写死，不许放宽：

- 学习：OCR 提取标题/关键词，生成 1–3 句「今天学了什么」+ 章节/页码；手写与公式易错，纪要必须可编辑，改后以用户版本为准。
- 饮食：识别菜品与主要食材；热量只给区间（如约 450–650 千卡）并标注「估算」，禁止显示精确到个位数的热量，允许用户改份量。
- 运动：照片只证明「到场」，推不出时长和消耗；时长/消耗只能来自计时器、手机健康数据或运动截图，纪要里每个字段逐项标注来源（AI 识别 / 运动截图 / 计时 / 健康数据 / 手填）。没有来源的字段留空显示「未记录」，不估算、不编造。

监督规则：

- 已盖章的卡可点赞、评论。评论时可勾选「质疑」并必须写一句理由，不勾选就是普通评论。
- 质疑计数：提出质疑的队友人数超过小队总人数一半即触发（5 人队需 3 名队友、3 人队需 2 名；打卡人本人不计票、不能质疑自己）。每人每天最多发起 2 次质疑。未过半不产生状态变化。
- 触发后：该卡变「待重打」，连续记录先冻结不扣回；打卡人次日 12:00 前按原计划重新打卡（验重打当天日期），盖章后恢复计入并解冻；逾期未重打则该日记未完成，原卡保留并标注「质疑成立，未重打」，不删除。质疑与重打全程留痕、双方可见。队长无权裁定质疑，只看人数。
- 逾期同步：计划截止时间过后 30 分钟仍未完成，系统自动在小队动态生成一条未完成动态（计划标志、计划名、截止时间），只提供「戳一下」一个动作，不许加 点赞 / 鼓励 / 评论。截止时间在 23:30 之后的，统一当天 23:30 同步，不跨天。每位队友对同一条动态可戳 1 次，被戳人收一条聚合推送。本人补上后动态自动更新为「已补上」并保留戳的记录，不删除。休息日 / 暂停周 / 已请假不生成逾期动态。注意：正常盖章卡才有点赞评论，逾期动态只有戳一下，两者不要混。

补卡规则：
每人每月 2 张；次日 12:00 前补前一天，同样验日期（验补卡当天）并写一句原因；补卡保本周完成率，连续记录冻结（不增、不清零，显示「冻结 1 天」）。补卡用完后漏打，连续记录归零重计，但历史总天数与历史周报永不清零。

周报规则：
周日 20:00 自动生成个人版 + 小队版。个人版含：称号式小结语（见下）、AI 事实总结、各计划应打/实打/补卡/完成率与连续变化、3 条纪要精选、跨品类汇总、一条下周建议（可一键采纳改计划）。两个分享动作都要做：「发送到小队动态」和「保存图片分享」（长图只含本人数据与称号，不带队友明细），都记为一次分享。生成后 24 小时内可补打卡并刷新一次。
称号按真实计数触发，每人每周 1 个主称号，只做正向与轻调侃、不生成负面称号：打卡次数全队第一 =「你是这周打卡最积极的人」；给队友评论数第一（质疑不计）=「你是本周的点评家」；被点赞+被评论合计最高 =「本周同伴盯着你打了 X 次卡」（X 为真实次数）；被戳次数最高且 >0 =「全队都在等你，你被戳了 X 次」；全勤无补卡 =「最稳的一个，零漏打」；完成率较上周提升最大 =「进步最大的人」。并列先比打卡次数，再并列同获；无人达标的称号空缺，不硬凑。

页面清单：
今日（首页）、打卡页、纪要确认页、小队页、计划页、周报页、历史页、建队/邀请页、我的页、设置页、通知中心。今日页固定布局：左上角显示本人头像（点头像进设置），右上角通知铃铛（带未读角标）+ 设置齿轮。设置页至少含：改头像（预设色或相册上传，换后全 App 本人头像同步）、昵称、通知总开关与分项开关（戳一下 / 逾期同步 / 周报 / 点赞评论 / 质疑）、隐私与可见范围、健康数据授权、补卡余量、暂停周。
小队页呈现：成员今日状态（已完成/进行中/未开始/已补卡，不显示「失败」字样）、动态流（盖章卡 / 逾期动态 / 周报卡）、小队共同连续天数（全员当日都完成才 +1）。

标志与视觉：
设计语言是「纸面收据 + 橡皮章」：米纸底色、深林绿、朱红印章色、高光黄点缀；打卡成功 = 盖一个章。具体色值、字阶、圆角以可交互原型为准，不要另起一套配色。
计划标志靠形状+颜色+文字三重区分，全程同一计划不变：ALL = 四格拼合圆章（墨绿底白字 ALL）；学习 = 翻开的书页章（墨绿）；运动 = 脚步印章（朱红）；饮食 = 餐盘圆章（高光黄底深字）；自定义 = 星形空心章（灰绿描边，可改名不可改形状）。
通知标志按事件分形：盖章成功 = 圆章对勾；质疑 = 带问号气泡；逾期 = 时钟；戳一下 = 手指；周报 = 柱状图；点赞/评论 = 心形/气泡。未读带朱红计数，已读变灰；质疑与逾期保留描边表示需要动作。

三条红线，任何情况下不许突破：

1. App 不经手钱：不做押金、对赌、分钱、红包池、付费代打。
2. 热量与运动消耗只写估算区间/有来源的数据，禁止伪精确，禁止靠一张照片推运动时长。
3. 不做连坐扣分、断签清零历史、面向陌生人的未完成公示、公开社区、陌生人组队、公开排行榜、课程内容、电商带货。

话术原则：
所有用户可见反馈只说事实和下一步，不说评价。例如不说「判定失败」，说「这张是昨天拍的，换一张今天的，或者现在拍一张」。

交付要求：

先输出：技术选型建议（含待定项清单）、里程碑拆分（按主流程 / 打卡与 AI / 质疑与逾期 / 周报四块）、数据模型草案，再开始写代码。每完成一块，对照本提示词逐条自检并列出未做项，不要把未实现的功能说成已完成。品类差异收进「证明方式 + 纪要字段模板」配置，新增品类只加配置和识别提示词，不改打卡主流程代码。
```

## 2. 全局铁律速查（贴在每个工位上）

这一节是第 1 节的速查版。任何 agent 的产出与这里冲突，以这里为准，并回头改产出，不要改这一节。

### 2.1 状态与规则速查

| 主题 | 定死口径 |
|---|---|
| 盖章 | 提交即盖章成功，**没有存疑、待确认状态**，AI 不负责拦人，只负责验日期、归类、生成纪要 |
| 默认分类 | 打卡默认 **ALL**，AI 自动归类（带置信度），可改标签后按新标签重新打卡；盖章后 24h 内可改标签 |
| 照片来源 | 实拍 / 当天相册图（验 EXIF 日期）/ 运动类当天截图（Keep 等，验画面内日期） |
| 非当天照片 | 单张剔除并提示；全部非当天才整单拦截；不计作弊、不留负面记录 |
| 质疑 | 评论勾选质疑 + 必写理由；队友质疑人数 **> 小队总人数一半** 触发（本人不计票）；每人每天最多发起 2 次 |
| 重打 | 次日 12:00 前，验重打当天日期；期间连续记录冻结不扣回，重打盖章后恢复 |
| 逾期动态 | 截止 +30 分钟未完成自动同步；23:30 后截止的一律 23:30 同步；**只有「戳一下」，没有点赞、鼓励、评论**；每人每条可戳 1 次 |
| 补卡 | 每月 2 张，次日 12:00 前补前一天，连续记录冻结不清零 |
| 周报分享 | 两个动作：发送到小队动态 / 保存图片分享；周日 20:00 生成，24h 内可刷新一次 |
| 今日页 | 左上角本人头像，右上角铃铛 + 设置齿轮，两个入口都能进设置 |

### 2.2 三条红线

1. **不经手钱**：押金、对赌、分钱、红包池一律不做（国内已有大厂同类玩法下线先例，合规风险高）。
2. **不伪精确**：饮食热量只给区间 + 标注「估算」；运动照片只证明到场，时长/消耗必须有计时、健康数据或截图来源，无来源就留空。
3. **不惩罚**：不连坐、不扣分、不断签清零历史、不公示未完成给陌生人。压力只来自「队友会看到」。

### 2.3 核心数据对象（字段以流程说明 V1.1 第 9 页为准，这里是最小集）

| 对象 | 关键字段 |
|---|---|
| Plan 计划 | 品类、目标文本、频率规则、时段与截止时间、证明方式、纪要字段模板、可见范围、状态（进行/暂停/结束） |
| Checkin 打卡 | 计划 ID（可为 ALL 待归类）、日期、照片数组（逐张来源 + EXIF 日期）、归类结果与置信度、标签修改记录、盖章状态、补卡标记 |
| Memo 纪要 | 打卡 ID、AI 摘要、结构化字段及逐项来源、用户修改版（最终展示以用户版为准） |
| Team 小队 | 成员与角色、共同连续天数、周完成率缓存 |
| Report 周报 | 周期、个人版/小队版内容、称号与触发计数、下周建议、分享状态 |
| Interaction 互动 | 打卡 ID、类型（点赞/普通评论/质疑评论）、内容、质疑理由、操作者、时间；质疑计数由质疑评论聚合得出 |
| OverdueFeed 逾期动态 | 计划 ID、截止时间、同步时间、被戳记录（谁、何时）、补上后状态 |

### 2.4 内测验收指标（4 周，5–8 个真实小队）

次周留存（建队用户）≥ 50% · 计划周完成率中位数 ≥ 70% · 自动归类准确率 ≥ 85%（以用户最终标签为准）· 纪要被修改率 ≤ 30% · 标签纠正率 ≤ 15% · 周报打开率 ≥ 80% / 分享率 ≥ 40% · 重打完成率 ≥ 70% · 戳一下响应率 ≥ 50%（被戳后当天完成计为响应）· 质疑率只观察不设上限。

## 3. 分角色专用提示词

每段自包含：复制整段发给对应 agent 即可。段内规则与第 2 节冲突时，以第 2 节为准并回报冲突，不要自行取舍。

### 3.1 产品经理 agent

```text
你是「打卡 App」的产品经理 agent。产品：2–5 人私密小队、各定各的计划（学习/饮食/运动）、拍照或上传当天照片证明、提交即盖章、AI 自动归类生成纪要、周日周报发给队友看。不经手钱、不做公开社区和排行榜。

你的任务：把《MVP 流程说明 V1.1》拆成可排期的需求文档与任务清单。
要求：
1. 按四块拆里程碑：主流程（建队/计划/单人模式）、打卡与 AI（验日期/自动归类/纪要）、监督（点赞评论/质疑重打/逾期同步/戳一下）、周报与激励。每块给用户故事、验收标准、依赖和风险。
```

### 3.5 AI / 算法 agent

